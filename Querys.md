# Referencia de Query Methods — Spring Data JPA

| Palabra clave | Función | Ejemplo de código | Resultado que produce |
|---|---|---|---|
| **`findBy`** | Busca uno o varios registros que cumplan la condición | `Optional<Usuario> findByCorreoInstitucional(String correo)` | Si existe `"juan@icesi.edu.co"`, devuelve `Optional[Usuario{id=5, nombre=Juan, ...}]`; si no existe, devuelve `Optional.empty()` |
| **`findBy` (lista)** | Busca varios registros; nunca `null`, si no hay resultados devuelve lista vacía | `List<Curso> findByDepartamento(String depto)` | Con `"Sistemas"` → `[Curso{Bases de Datos I}, Curso{Programación II}, ...]`; si no hay ninguno → `[]` |
| **`existsBy`** | Responde sí/no sobre si existe al menos un registro (sin traer datos) | `boolean existsByCorreoInstitucional(String correo)` | Con `"juan@icesi.edu.co"` ya registrado → `true`; con un correo nuevo → `false` |
| **`countBy`** | Cuenta cuántos registros cumplen la condición | `long countByDepartamento(String depto)` | Con `"Sistemas"` (si hay 12 cursos de ese depto) → `12` |
| **`And`** | Exige que ambas condiciones se cumplan a la vez | `List<Profesor> findByDepartamentoAndActiveTrue(String depto)` | Con `"Sistemas"` → solo profesores de Sistemas que además estén activos, ej. `[Profesor{Ana, activo}, Profesor{Luis, activo}]` (excluye a los inactivos aunque sean de Sistemas) |
| **`Or`** | Basta que se cumpla una de las dos condiciones | `List<Flight> findByOriginAirport_CityOrDestinationAirport_City(String c1, String c2)` | Con `("Bogota", "Bogota")` → vuelos que salen de Bogotá **o** llegan a Bogotá, ej. `[Flight{AN101, Bogota→JFK}, Flight{GA402, Madrid→Bogota}]` |
| **`True` / `False`** | Atajo para filtrar un campo booleano | `List<Profesor> findByActiveTrue()` | Devuelve solo los profesores con `active = true`, ej. `[Profesor{Ana}, Profesor{Luis}]` (omite a los que tienen `active = false`) |
| **`Between`** | Filtra un rango cerrado (incluye ambos extremos) | `List<Curso> findByCreditosBetween(int min, int max)` | Con `(2, 4)` → cursos con 2, 3 o 4 créditos, ej. `[Curso{Cálculo, 3 créditos}, Curso{Física, 4 créditos}]` (excluye uno de 5 créditos) |
| **`GreaterThanEqual`** | Filtra valores mayores o iguales a un umbral | `List<Curso> findByCreditosGreaterThanEqual(int minimo)` | Con `4` → cursos con 4 o más créditos, ej. `[Curso{Física, 4}, Curso{Tesis, 6}]` (excluye uno de 3 créditos) |
| **`LessThan`** | Filtra valores estrictamente menores | `List<Curso> findByCreditosLessThan(int maximo)` | Con `4` → cursos con menos de 4 créditos, ej. `[Curso{Cálculo, 3}]` (excluye el de exactamente 4) |
| **`Containing`** | Busca fragmentos de texto (equivale a `LIKE %texto%`) | `List<Curso> findByNombreContaining(String fragmento)` | Con `"Base"` → `[Curso{Bases de Datos I}, Curso{Bases de Datos II}]` (cualquier nombre que contenga "Base") |
| **`IgnoreCase`** | Ignora mayúsculas/minúsculas en la comparación | `List<Curso> findByNombreContainingIgnoreCase(String fragmento)` | Con `"base"` (minúscula) → sigue encontrando `[Curso{Bases de Datos I}]` aunque el nombre real tenga "B" mayúscula |
| **`OrderBy...Asc`** | Ordena los resultados de menor a mayor | `List<Profesor> findByEspecialidadOrderByApellidoAsc(String esp)` | Con `"IA"` → `[Profesor{Acosta}, Profesor{Gómez}, Profesor{Pérez}]` (alfabético A→Z por apellido) |
| **`OrderBy...Desc`** | Ordena los resultados de mayor a menor | `List<Flight> findByArrivalDateBetweenOrderByEstimatedPassengersDesc(Timestamp d, Timestamp h)` | `[Flight{estimatedPassengers=310}, Flight{280}, Flight{198}]` (de más pasajeros a menos) |
| **`_` (guion bajo)** | Navega a un atributo de una entidad relacionada | `List<Curso> findByProfesor_Departamento(String depto)` | Con `"Sistemas"` → cursos cuyo **profesor** pertenece al departamento de Sistemas, ej. `[Curso{Redes, profesor.departamento=Sistemas}]` |
| **`@Query` (JPQL)** | Consulta manual usando nombres de clases/atributos Java | `@Query("SELECT ec.estudiante FROM EstudianteCurso ec WHERE ec.curso.id = :id") List<Estudiante> buscarPorCurso(@Param("id") Long id)` | Con `id=3` → `[Estudiante{Laura}, Estudiante{Pedro}]` (todos los estudiantes matriculados en el curso 3) |
| **`@Query` (nativeQuery = true)** | Consulta manual usando nombres de tabla/columna reales de la BD | `@Query(value = "SELECT * FROM estudiante WHERE active = true", nativeQuery = true) List<Estudiante> buscarActivos()` | `[Estudiante{Laura, active=true}, Estudiante{Ana, active=true}]` (excluye los inactivos, ejecutando SQL literal) |
| **`@Modifying`** | Marca una consulta que modifica datos (`UPDATE`/`DELETE`), no solo lee | `@Modifying @Query("UPDATE Curso c SET c.activo = false WHERE c.id = :id") int desactivar(@Param("id") Long id)` | Devuelve `1` (una fila modificada) si el curso existía y se desactivó; `0` si no existía ningún curso con ese id |
| **`@Transactional`** | Garantiza que todas las operaciones se completen juntas, o ninguna | `@Transactional(rollbackFor = Exception.class) public EstudianteCurso matricular(...)` | Si todo sale bien → la matrícula queda guardada; si algo falla a mitad de camino (ej. excede créditos) → **nada** queda guardado, ni siquiera lo que ya se había insertado antes del error |
| **`@Transactional(readOnly = true)`** | Optimiza consultas de solo lectura (sin cambios) | `@Transactional(readOnly = true) public Page<Curso> listarPaginados(...)` | Mismo resultado que sin la anotación, pero más eficiente (Hibernate no rastrea cambios en los objetos) |
| **`Page<T>`** | Trae una "página" de resultados + metadatos (total de páginas, etc.) | `Page<Curso> findByDepartamento(String depto, Pageable pageable)` | Con `page=0, size=2` sobre 5 cursos de Sistemas → `Page{content=[Curso1, Curso2], totalElements=5, totalPages=3}` |
| **`Slice<T>`** | Trae una "porción" de resultados, sin contar el total (más liviano) | `Slice<Curso> findByDepartamento(String depto, Pageable pageable)` | Con `page=0, size=2` → `Slice{content=[Curso1, Curso2], hasNext=true}` (no sabe cuántos hay en total, solo si hay más) |
